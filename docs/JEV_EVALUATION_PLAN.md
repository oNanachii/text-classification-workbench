# Jev 对照的新数据版本计划

计划状态：尚未采集、标注或运行付费评测；当前只完成工程能力和合成烟测。现有 `jev-authored-smoke-v1` 的 4 条 AI 自编短信不作为质量、准确率或中文能力证据。

## 首轮范围与版本

新版本暂命名 `sms-jev-comparison-v1`，仅英文单条短信，标签 `ham/spam`，沿用 `JEV_API_CONTRACT.md` 的任务定义。同一条原文同时送既有本地实际加载模型与固定 `jev-1.14.0`；保留原始文本与两条推断路径的预处理说明。本地模型仍使用其冻结词表与阈值，不为新对照修改旧模型。另报告不支持的语言、无已知词汇、超长输入及外部失败，不能从分母中静默移除。

若后续产品改为中文留言分流，必须建立另一任务 ID、标签指南、来源与评测版本；当前英文模型不可宣称适用于该任务，也不可直接作中文效果排名。

## 数据与人工标注

先得到来源授权和外发 TypeSafe 的许可，避免使用敏感原文。至少覆盖普通个人消息、事务通知、已订阅推广、未经请求推广、奖品诱导、诈骗与困难边界；按来源和时间记录占比。正式样本量应由希望识别的误拦率/差异精度决定，当前不虚构固定样本量或统计保证。

由至少两名独立人工标注者在看不到模型建议的情况下标注。标签分歧保留并裁决；不以模型一致作为真值。记录指南版本、标注者匿名 ID、裁决理由、标注时间，以及不确定/不适用状态。人工最终标签与模型建议分开保存。

建立来源、时间窗口及近重复组 ID，然后整组划分开发集与新封存测试集。划分前审计文本规范化重复、模板近重复及跨来源转发；不能把现有 757 条已开封测试或其近重复内容纳入新的独立测试。旧测试只保留历史报告，本计划不重新读取其原文。

## 预先固定与执行

开发集可以检验提示、人工复核阈值和失败策略；每次配置有独立版本。正式测试前冻结数据清单摘要、标签准则、划分、Jev 模型 ID、问题/标签描述 SHA-256、本地模型/快照/阈值、超时、失败处理和人工复核规则。保留最终计划且一次执行；不使用测试结果继续选择候选后仍称原测试为独立证据。

执行工具应默认 dry-run；付费请求、批量数量和预算上限须明确授权。请求不得隐式重试，超时/连接不确定的样本记为 unknown，先核对用量再决定是否另外授权重试。批量执行是后续工作，当前 API 仅支持单条。

## 报告字段与结论边界

每个样例仅在私有受控评测空间保留文本；公开报告只用不反查原文的样例 ID。记录数据版本、模型/提示版本、标签、概率含义、confidence 类型、耗时、输入/输出 token、成功/失败/unknown 状态、分歧、人工真值与裁决记录。

分别报告：混淆矩阵、垃圾 precision/recall、macro-F1、正常消息误拦率、垃圾漏检率、失败/unknown 比例、待人工复核比例、耗时分布与实际用量。比较应给同一样本的配对差异和不确定区间；分层样本的总体指标须说明目标分布/权重。若要评价人工成本，另计复核时间和处理负担。

Jev confidence 是分布集中程度；验证其与正确率关系需要新数据上的可靠性/校准分析，不能直接用 confidence 替代准确率。模型分歧只是人工关注信号；一致也不代表正确。旧英文留出成绩、工程测试、合成烟测和未来业务效果分别展示。
